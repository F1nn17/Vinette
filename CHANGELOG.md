# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- The notice "No connection" above the list also appears when the live updates cannot be restored for more than three seconds, although the browser thinks it is online (for example when the server restarts). What was loaded stays on the screen; the notice goes as soon as the connection is back, and the list is read again.
- New mail appears in the list while the mailbox is open, without reloading: a message that arrives is put at the top of the inbox (and of the "Unread" or "Flagged" view, if it belongs there), the counters in the sidebar follow, marks set in another mail program (read, flag, labels) show on the rows and in the open message, and messages removed elsewhere leave the list. If the connection is lost, the screen tries again with growing pauses and reads everything again when it is back.
- A real-time channel at `/hubs/mail` (SignalR): a signed-in browser connects and is sent the changes of its inbox as they happen (a message arrived, messages were removed, marks or counters changed, or the folder must be read again). It needs the session cookie, is closed within half a minute after the session ends, and sends nothing of another mailbox. The screen starts using it with the next real-time task.
- What the mail server reports about the inbox is turned into events the screen can use: a message arrived (with its line of the list), messages were removed, the marks of a message changed (read, flag, replied to, labels), the counters changed, or the folder must be read again (a big burst of mail). Several notices that come together are answered once. The events reach the screen with the next real-time tasks.
- The mail server is now followed for new mail without being asked: one connection per mailbox (shared by all the browsers and devices signed in to it) waits for the server's notifications about the inbox and is closed a minute after the last browser is gone. New settings `Imap:IdleRestart` (default 25 minutes, at most 29), `Imap:IdleGrace` (1 minute) and `Imap:MaxIdleConnections` (200, apart from the limits on the connections that answer requests). Count one more connection per mailbox when you set `mail_max_userip_connections` on Dovecot. The notifications reach the screen with the next real-time tasks.
- The key `l` opens the "Labels" panel for the selected messages, or, with nothing selected, for the open message; it is listed in the window of keyboard shortcuts.
- The trash and the spam folder can be emptied: a button under the list heading asks first ("All messages in this folder will be deleted forever. This cannot be undone."), then deletes everything. In the trash, an open message and a selection have a "Delete forever" button (also after a question) in place of "Delete"; there is no "Undo" for these.
- `POST /api/v1/folders/{folder}/empty` deletes every message of the trash or of the spam folder for good (`{"deleted": N}`; any other folder is refused with 409 `not_in_trash`), and `POST /api/v1/messages/batch` takes the action `delete` for messages of the trash (up to 100).
- Labels in the interface: the "+" next to "Labels" in the sidebar makes a new label, the "..." of a label changes its color (Work, Bills, Personal), renames it or deletes it (after a question; the messages stay), and a click on a label shows the messages that have it from all folders except the trash and spam (the newest 50, no filters or selection there). An open message and a selection have a "Labels" button: a panel with a box for each label (half full when only some of the selected messages have it) and a field for a new label.
- `GET /api/v1/labels/{name}/messages` lists the newest messages with a label (`limit` 1 to 100, 50 by default) from every folder except the trash and the spam folder, newest first; there is one page, `total` says how many messages have the label.
- Keyboard shortcuts in the mailbox: `j` and `k` move through the list (a ring marks the row; with a message open they open the next or previous one), `Enter` opens the message under the cursor, `e` archives, `#` deletes (to the trash), `/` goes to the search field, `c` starts a new message, and `?` opens the "Keyboard shortcuts" window, the only place the keys are explained. They apply to the selected messages, or to the open one if nothing is selected. The keys work in the Russian layout, are silent while typing, and leave Ctrl/Alt/⌘ combinations to the browser.
- After a message is archived, marked as spam or deleted (from the open message or from a selection), a message at the bottom of the screen says so and offers "Undo": it puts the messages back in the folder they came from. The message comes back with a new identifier, as the mail server numbers messages per folder.
- Archiving, marking as spam, deleting and marking as read or unread show their result at once: the message leaves the list and the counters of the folders change before the mail server has answered. If the server refuses, everything comes back (including the selection) and a short message at the bottom of the screen says what happened. Errors of these actions are now shown there instead of inside the panel.
- The buttons of an open message work: archive, spam and delete (the message goes to the trash), and the flag. "More" offers "Mark as unread" and, on a phone, where the bar has no action buttons, all of the actions. After an action the screen goes back to the list; if the mailbox has no folder for it (archive, spam or trash), the message says so and stays.
- Several messages can be selected in the list: a box appears at the left of a row on hover (Ctrl/⌘ and a click select a row, Shift and a click a range; on a phone, a long press), and while messages are selected the heading of the list gives way to "Selected: N", "Select all" and the actions archive, spam, delete and mark as read. At most 100 messages can be selected at a time. `POST /api/v1/messages/batch` applies one action to up to 100 messages of one folder.
- Labels on messages through the API: `GET/POST /api/v1/labels`, `PATCH/DELETE /api/v1/labels/{name}` and `PATCH /api/v1/messages/{id}/labels`. A label is an IMAP keyword on the message, so other mail programs see it and it stays when the message is moved; the list of labels (a label can exist before any message has it) and the colors (`work`, `bills` or `personal`) are kept in the user's settings. A simple name (`Work`) is the keyword as it is; any other name (spaces, Cyrillic) is kept as `vl-` and a code, which only Vinette reads back, so it can be at most about 14 letters long. Renaming or deleting a label changes every message that has it, in every folder. The chosen color is shown on the label in the list and in the message.
- Actions on a message through the API: `POST /api/v1/messages/{id}/archive`, `/spam`, `/trash`, `/move` (with `{"to": "<folder path>"}`) and `DELETE /api/v1/messages/{id}` to delete for good (only a message that is in the trash). A move answers with the message's new id and folder, so that it can be put back. A mailbox without an archive, spam or trash folder gets `409 no_target_folder`. Moving uses IMAP MOVE, or COPY + mark + expunge of that one message on a server without it. The buttons in the interface follow in a later release.
- "Always show" for the pictures of a sender: under the notice about hidden images, a message from a verified sender offers to show that sender's pictures right away from now on, and the choice can be withdrawn from the same place. The sender is remembered by the exact address, in the user's settings (`trustedImageSenders` in `GET /api/v1/settings`; `PATCH` accepts `trustImagesFrom` and `untrustImagesFrom`). The pictures are loaded without asking only when your mail server's checks confirm the sender, because the From line can be forged; otherwise they stay hidden behind the usual "Show" button.
- External images of a message can be shown: the notice about hidden images has a "Show" button. The server fetches the pictures itself and puts them into the message, so the sender never sees the reader's address or the time of opening, and the reader's browser makes no request to the sender's server. Only public addresses on ports 80 and 443 are fetched (never the server's own network, cloud metadata or private addresses, also after redirects and name lookups), at most 2 MB per picture, 10 MB and 30 pictures per message, 5 seconds per picture; only real PNG, JPEG, GIF and WebP pictures are kept (never SVG). A picture that could not be loaded stays hidden and the notice says so. `GET /api/v1/messages/{id}?images=true` does it; the message tells whether pictures can be shown (`canShowImages`) and how many were (`imagesShown`).
- The `ExternalImages` settings (`Enabled`, `MaxImageBytes`, `MaxTotalBytes`, `MaxImages`, `RequestTimeout`, `TotalTimeout`, `MaxRedirects`, `AllowedPorts`) tune this; `ExternalImages:Enabled=false` turns it off, and the pictures then stay hidden for everyone. `AllowPrivateAddresses` is for tests only.
- A very long message is shown cut: only the first 250 000 characters of its text are cleaned and shown, with the notice "This message is very long: only the beginning is shown." and a "Show all" button that loads up to 1 000 000 characters. Markup built to keep the server busy is cleaned or refused within seconds (5 seconds at most, then the plain text is shown instead).
- `Imap:MaxViewableMessageBytes` (default 33554432, 32 MB) limits the size of a message that is loaded to be shown or to have an attachment downloaded; a bigger one is refused without being downloaded.
- On a phone a message opens full screen with a "Back" button first in its action bar (and the browser's own Back works too). The list keeps what it had loaded and where it was scrolled to, and the focus goes back to the message that was open. The buttons of the action bar are at least 44 px high.
- Opening a message marks it as read (the dot in the list and the unread counter of the folder follow at once), and the flag button works: it sets and removes the flag, and goes back with a clear message if it cannot be saved. `PATCH /api/v1/messages/{id}/flags` changes the read and flag marks.
- Attachments of an open message are listed under its text, two cards per row with the file type, name and size, and are downloaded with one click or with Tab and Enter. Files are always saved, never opened in the browser.
- Messages can be read: selecting one in the list opens it in the reading area with its subject, labels, sender, recipients, date, a confirmation or a warning from the sender check, a notice when external images were hidden, and the body in a sandboxed frame. The action buttons (reply, forward, archive, spam, delete, flag) are shown but not active yet.
- A message now says whether its sender passed the checks of your mail server (`sender`: `verified`, `suspicious` or `unknown`, from the `Authentication-Results` header). "Verified" is believed only from the topmost header of your own server: set `SenderCheck:TrustedAuthservIds` (`VINETTE_SenderCheck__TrustedAuthservIds__0`) to the name your server writes at the start of that header if it is not the address in `Imap:Host`. A failed check is reported whichever server wrote it.
- `GET /api/v1/messages/{id}/attachments/{partId}` downloads an attached file: always as a download (never shown in the browser), with a safe file name, `nosniff` and a type from a short list of harmless ones (HTML, SVG and anything unusual are sent as plain bytes). An attached mail is downloaded as an `.eml` file.
- Pictures that belong to a mail (inline images sent with it) are shown in its body: they are embedded into the page (PNG, JPEG, GIF, WebP up to 1 MB each and 8 MB per message, recognized by their content, never SVG), so opening a message needs no further request for them.
- `GET /api/v1/messages/{id}` opens a message for reading: headers, all recipients, flags, the body as cleaned HTML (the sender's HTML with active content removed, or the plain text with links and quotations; external pictures are taken out and counted) and the list of attachments. Opening does not mark the message as read; a message larger than 32 MB is refused with `payload_too_large`.
- The list options button (next to refresh) switches the message list between the comfortable and the compact density; the compact one has lower rows without the preview and does not ask the mail server for previews. The choice is saved per mailbox (`GET` and `PATCH /api/v1/settings`) and kept after a reload and on other devices. On a phone the list always shows the preview.
- User settings (list density, language, label colors) are kept on the server per mailbox in files under `Settings:Path` (`VINETTE_Settings__Path`; `/data/settings` in the Docker image, `/var/lib/vinette/settings` in the systemd unit). Keep the directory on persistent storage; it is part of what to back up.
- The mailbox screen on a phone follows the mobile design: a header with the menu button, the folder title, a search button and the account, the filter chips, rows with the sender's avatar and the unread dot beside the preview, and a floating "Compose" button. Filter chips have a touch-friendly hit area.
- The message list is virtualized: only the rows near the visible part exist in the page, so a folder of tens of thousands of messages scrolls smoothly. The next page loads by itself when you get close to the end of what is loaded (the "Show more" button is gone). The header and filters stay in place while the list scrolls.
- The message list shows a banner while the browser has no connection; what was already loaded stays on screen. Loading, empty and error states of the list are covered by component tests.
- The message list is split under headings by date: Today, Yesterday, Earlier this week, then one heading per month (with the year for earlier years). Days change at the user's local midnight.
- The mailbox screen shows the message list: the folder title with the number of unread messages, a refresh button, a search box (not wired yet), the "All / Unread / Flagged" filters (kept in the address, so a reload keeps them), and the messages with sender (recipient in Sent and Drafts), subject, preview, labels, unread, flag and attachment marks, and a date as in the design. More messages are loaded with "Show more". Opening a message puts its address in the URL.
- The mailbox screen has a sidebar: logo, the mailbox address, a "Compose" button, the folders with counters (unread messages; the number of drafts for Drafts), a "Flagged" view right after the inbox, a labels section and the used storage. On a tablet it is a rail of icons. The current folder is highlighted and everything can be reached with the keyboard.
- The mailbox screen has its frame: three columns (folders, list, reading area) on a desktop of 1200 px and wider, a narrow folder rail beside list and reader on a tablet (768–1199 px), and a single column with a folder drawer on a phone. A message has its own address, `/mail/<folder>/<message>`.
- The message list now carries a one-line text preview (up to 200 characters) for every message, also for servers that cannot make previews themselves, and for messages in quoted-printable, base64, KOI8-R or Windows-1251. `preview=false` leaves it out.
- The message list can be narrowed with `filter=unread` or `filter=flagged` (default `all`). The filter works together with paging and order, and `total` then counts the matching messages.
- `GET /api/v1/folders/{folder}/messages`: the messages of a folder, newest first (or oldest first with `order=oldest`), 50 per page (up to 100): sender, recipients, subject, date, read/flagged/answered/draft marks, attachment mark, labels, size. Pages are followed with the `next` cursor, so new or deleted mail never shifts or repeats them, and a folder with tens of thousands of messages is as fast as a small one.
- `GET /api/v1/quota`: how much of the mailbox's storage is used and the limit, in bytes. The `storage` field is absent when the mail server reports no storage limit, so the web app shows nothing then.
- Servers that do not mark their special folders are handled too: Drafts, Sent, Archive, Spam and Trash are found by their usual names (English and Russian, also inside `INBOX` or `[Gmail]`). The web app shows these folders under its own names in the interface language, whatever the server calls them.
- `GET /api/v1/folders`: the folders of the signed-in user's mailbox in sidebar order (Inbox, Drafts, Sent, Archive, Spam, Trash, then own folders with sub-folders after their parent), each with its role, total and unread counts.
- Messages are identified by folder, folder version (`UIDVALIDITY`) and message number in the API as one opaque string, e.g. `SU5CT1g.1731000000.42`. If a folder was deleted and created again on the mail server, requests with old ids get `409` with the error code `uid_validity_changed` and the web app reloads what it showed instead of opening a wrong message.
- When the mail provider stops accepting the saved password (changed or revoked), the user is signed out and the login screen explains why ("Your mailbox password has changed or access was closed. Sign in again."). Plain-language texts for "mail unavailable" and "mail busy" are ready for the mailbox screens; the error table is in `docs/api-errors.md`.
- Metrics for administrators: `GET /metrics` in the Prometheus format, off by default. Set `Metrics:Enabled` to `true` and `Metrics:BearerToken` (at least 16 characters; the application does not start without it); the scraper sends `Authorization: Bearer <token>`. Mail connection metrics: `vinette_mail_connections_open`, `..._opened_total`, `..._closed_total{reason}`, `vinette_mail_commands_queued`, `vinette_mail_command_duration_seconds` (histogram), `vinette_mail_errors_total{kind}`, `vinette_mail_reconnects_total`. No addresses or other personal data in labels. Do not publish `/metrics` through the public reverse proxy.
- Limits on open mail connections: `Imap:MaxConnectionsPerUser` (default 5, one per signed-in browser or device) and `Imap:MaxConnections` (default 200). When all places are taken, a request waits up to `Imap:ConnectionWaitTimeout` (10 s) and then gets `503` with `Retry-After` and the error code `mail_busy`.
- Mail connections of signed-in users are closed after `Imap:ConnectionIdleTimeout` without activity (default 5 minutes) and when the application stops; the next request opens a new one. Long-idle users no longer hold connections on the mail server.
- Optional Redis session store for running several instances behind one address: set `Session:Store` to `Redis` and `Redis:ConnectionString` (StackExchange.Redis format, e.g. `redis:6379,password=...,ssl=true`); `Redis:KeyPrefix` (default `vinette:`) lets Vinette share a Redis with other applications. Sessions then survive a restart and are valid on every instance; they expire in Redis by themselves. The default stays `InMemory`. The sign-in limits are still counted per instance. The Redis password is part of the connection string: keep it in an environment variable or a protected config file.
- The sign-in screen: address and password (with show/hide), "stay signed in" option, clear messages for a wrong password, unavailable mail and too many attempts, and a brand panel that uses the configured name and tagline (`Branding:Tagline`).
- The mailbox and compose pages now require sign-in: a signed-out visitor is sent to the login screen and, after signing in, back to the page they asked for. If the server ends the session (timeout, sign-out elsewhere), the app signs the user out and drops everything cached for them.
- Real client address behind a reverse proxy: new key `Security:TrustedProxies` (addresses or CIDR networks, e.g. `10.0.0.0/8`) lists the proxies whose `X-Forwarded-For`, `X-Forwarded-Proto` and `X-Forwarded-Host` headers are believed. Empty by default: the headers are ignored. `0.0.0.0/0` and `::/0` are refused at startup. The client address is used for sign-in limits, the sign-in log, the per-request `ClientIp` log field and the mail server's `ID` command (`x-originating-ip`; Dovecot honors it only from `login_trusted_networks`).
- Brute-force protection for sign-in: after 5 wrong passwords a mailbox is locked for 1 minute, and every further failure doubles the lock up to 15 minutes; a client address is locked after 20 failures; at most 30 sign-in requests per minute per client address. Locked attempts answer `429` with `Retry-After` without contacting the mail server. Tunable with `Security:LoginRateLimit:*`. Counters are per instance and kept in memory. Behind a reverse proxy set `Security:TrustedProxies`, otherwise all users share the proxy's address.
- CSRF protection: every state-changing API request (POST, PUT, PATCH, DELETE) must carry an anti-forgery token in the `X-CSRF-Token` header (issued by `GET /api/v1/csrf`) and come from a page of the application (`Origin`/`Referer` check; the real-time hub is checked by `Origin`). New optional key `Security:TrustedOrigins` lists extra allowed origins (for example a front-end dev server or an unusual proxy setup). Scripts that call the API without a browser must send both headers.
- `GET /api/v1/me` returns the signed-in mailbox. All API endpoints and the real-time hub now require a signed-in session by default (`401` as `problem+json` otherwise); only health, sign-in/out, branding files, the OpenAPI document (development) and the web app itself are public.
- Sign-in API: `POST /api/v1/auth/login` (address, password, "stay signed in") and `POST /api/v1/auth/logout`. The session id is kept in the `__Host-vinette_session` cookie (`HttpOnly`, `Secure`, `SameSite=Strict`); sign-in therefore needs HTTPS (or `localhost`). Failed and successful sign-ins are logged with the address and client IP, never the password.
- Sessions: signed-in users are kept in server memory with the mailbox password encrypted (ASP.NET Core Data Protection); a session ends after `Session:IdleTimeout` of inactivity or `Session:MaxLifetime` after login. New key `Session:RememberMeLifetime` (default 30 days) for "stay signed in" sessions. Without `DataProtection:KeysPath` the application warns at startup that all users are signed out on every restart.
- Configuration keys `Imap:Timeout` (limit for connecting and for each reply of the mail server, default 30 s: Dovecot slows down failed logins by up to ~15 s) and `Imap:AllowInvalidCertificate` (accept any TLS certificate of the mail server; off by default, for development servers with self-signed certificates only).
- API errors are returned as `application/problem+json` (RFC 9457) with a machine-readable `code` and a `correlationId`; every response carries an `X-Correlation-Id` header that also appears in the logs.
- Design specification (`docs/design/DESIGN.md`), design tokens wired into Tailwind v4, Golos Text font bundled locally, brand icons and web manifest.
- UI primitives (Button, IconButton, Chip, LabelTag, Avatar, Badge, TextField, TextArea, Select, Checkbox, ProgressBar, Logo) with tests and a dev-only `/dev/ui` catalogue.

- Project scaffold: backend (ASP.NET Core, .NET 10) and frontend (React + Vite) skeletons, build tooling, CI/CD, Docker and systemd deployment, documentation.

### Changed

- The application now runs on .NET 11 (it was .NET 10). The Docker image is built on `dotnet/sdk:11.0` and runs on `dotnet/aspnet:11.0-resolute-chiseled` (Ubuntu 26.04 base); a server without Docker needs the ASP.NET Core 11 runtime. See ADR-0005.

### Fixed

- "Mark as unread" on a message that was already read when it was opened no longer reads it again at once: opening a message reads it only if it was unread when it was opened.
- An attachment whose base64 data lacks the closing `=` padding is now read to its end (its last, shorter group was dropped before), after the update of the mail library.
- A link to a message (`/mail/<folder>/<message>`) opens the application after a page reload and from a bookmark; it answered with an error before.
- Subjects, senders and previews written in KOI8-R, Windows-1251 and other legacy charsets are shown correctly in the message list (the application did not load these charsets before).
- A request parameter the server cannot read (e.g. `limit=abc`) now answers `400` with a problem body instead of `500`.
