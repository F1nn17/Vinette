# Политика безопасности

## Как сообщить об уязвимости

**Не создавайте публичные issues и pull requests** для сообщений об уязвимостях.

Используйте приватную отправку через GitHub Security Advisories: вкладка **Security** → **Report a vulnerability** в репозитории.

Пожалуйста, укажите:

- описание проблемы и её влияние;
- шаги воспроизведения или proof of concept;
- затронутую версию.

Мы подтвердим получение сообщения и сообщим о дальнейших шагах. До выхода исправления просим не раскрывать детали публично.

Последний аудит безопасности и его результаты — [docs/security-audit.md](docs/security-audit.md).

## Поддерживаемые версии

Исправления безопасности выпускаются для последней минорной версии.

## Что хранится на сервере

- **Ключи шифрования пароля.** Каталог `DataProtection:KeysPath`: без `DataProtection:CertificatePath` ключи лежат открытым XML, и тот, кто читает каталог, расшифрует сохранённые пароли; с сертификатом (`.pfx`) ключи на диске зашифрованы, а сертификат и его пароль нужно хранить отдельно от каталога и его копий ([docs/data-protection-keys.md](docs/data-protection-keys.md)).
- **Пароль почты.** Только на сервере и только зашифрованным (ASP.NET Core Data Protection), в браузер не отправляется. Он лежит в сессии; и, **пока в очереди ждёт отложенное письмо** («Отправить позже», [ADR-0008](docs/adr/0008-scheduled-send.md)), его зашифрованная копия лежит в каталоге очереди (`Scheduling:Path`) рядом с письмом. Эта копия зашифрована отдельным назначением и с ограниченным сроком жизни (до отправки плюс время на повторы и сутки), удаляется вместе с письмом при отправке, отмене и отказе и в журналы не попадает. Каталог данных и ключи Data Protection нужно беречь одинаково: у кого есть оба, тот прочтёт пароль ожидающего письма.
- **Отложенная отправка** можно отключить на экземплярах, где она не нужна (`Scheduling:Enabled=false` отключает только отправку: письма можно ставить и отменять через любой экземпляр).
