# Ошибки API

Все ошибки `/api/v1` возвращаются в формате ProblemDetails ([RFC 9457](https://www.rfc-editor.org/rfc/rfc9457)) с типом `application/problem+json`. Это касается и необработанных исключений, и ошибок валидации, и «пустых» ответов 4xx/5xx (например, 404 для неизвестного маршрута).

## Формат

```json
{
  "type": "urn:vinette:error:validation_failed",
  "title": "One or more validation errors occurred.",
  "status": 400,
  "code": "validation_failed",
  "correlationId": "5f1c0a8e3b2d4c6f9a7e1d2b3c4a5f60",
  "errors": { "email": ["The Email field is required."] }
}
```

| Поле | Назначение |
| --- | --- |
| `type` | `urn:vinette:error:<code>` |
| `title`, `status` | стандартные поля RFC 9457; `title` — не для показа пользователю |
| `code` | машиночитаемый код из каталога ниже; по нему фронтенд выбирает понятный текст (i18n) |
| `correlationId` | идентификатор запроса; совпадает с заголовком `X-Correlation-Id` и с полем `CorrelationId` в логах |
| `errors` | только для `validation_failed`: поля и сообщения |
| `detail` | только в Development (текст исключения); в продакшене никогда не заполняется |

Внутренние детали — трассировки стека, тексты исключений, адреса серверов — клиенту не отдаются.

## Каталог кодов

Источник: [ErrorCodes.cs](../backend/src/Vinette.Api/Errors/ErrorCodes.cs). Новый код добавляйте и там, и здесь, и в словари i18n фронтенда.

| Код | HTTP | Когда |
| --- | --- | --- |
| `bad_request` | 400 | запрос не разобран или неверен |
| `validation_failed` | 400 | не прошла валидация полей (`errors`) |
| `unauthorized` | 401 | нет сессии или она истекла |
| `invalid_credentials` | 401 | неверный адрес или пароль при входе (ответ одинаков для неверного пароля и несуществующего ящика) |
| `forbidden` | 403 | действие запрещено (например, не прошла CSRF-проверка) |
| `not_found` | 404 | ресурс или маршрут не найден |
| `conflict` | 409 | конфликт состояния |
| `payload_too_large` | 413 | слишком большой запрос или вложение |
| `too_many_requests` | 429 | сработал rate limiting; см. `Retry-After` |
| `internal_error` | 500 | непредвиденная ошибка сервера |
| `mail_unavailable` | 503 | почтовый сервер недоступен или не прошёл проверку TLS при входе |
| `service_unavailable` | 503 | временная недоступность (почтовый сервер, перегрузка) |

Обработчик может задать более точный код сам, указав `Extensions["code"]`; если не задал, код выводится из HTTP-статуса.

## Correlation id

- Клиент может передать `X-Correlation-Id` (1–64 символа: буквы, цифры, `.`, `_`, `-`). Иначе сервер генерирует идентификатор; некорректное значение заменяется.
- Идентификатор возвращается в заголовке ответа `X-Correlation-Id` и попадает в область логирования (`CorrelationId`) всех записей запроса.
- По нему администратор находит запись в логах по обращению пользователя.

## Для разработчиков

- Возвращайте ошибки через `Results.Problem(...)` / `Results.ValidationProblem(...)` или бросайте исключение — не формируйте JSON вручную.
- Конвейер подключается `AddVinetteProblemDetails()` и `UseVinetteProblemDetails()` (первым в конвейере).
- Встроенная валидация DTO (`AddValidation`) включена; первый реальный DTO с атрибутами валидации появится вместе с входом (VIN-020), тогда же нужен интеграционный тест на неё.
