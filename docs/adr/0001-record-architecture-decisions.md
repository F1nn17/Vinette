# 1. Фиксируем архитектурные решения

Статус: принято

## Контекст

Проекту нужен способ сохранять причины ключевых решений, чтобы новые участники и агенты не пересматривали их заново.

## Решение

Используем Architecture Decision Records (ADR) в `docs/adr/`: один файл на решение, имя `NNNN-кратко-о-решении.md`, разделы «Контекст», «Решение», «Последствия». Принятые ADR не переписываются — их заменяют новыми с пометкой в статусе.

## Последствия

Любое решение, меняющее стек, лицензию или архитектурные границы, сопровождается ADR.
