# Аудит безопасности (VIN-122)

Дата: 2026-11-27. Версия: `main` на коммите VIN-121 (заголовки и CSP) плюс исправления этого аудита. Объём: чек-лист из раздела 10 [AGENTS.md](../AGENTS.md) и то, что к нему примыкает (аутентификация, сессии, CSRF, заголовки, журналы, письма как недоверенный контент, зависимости, образ).

Метод: чтение кода по каждому пункту; автоматические тесты, которые остаются в репозитории; ручная проверка на **настоящем контейнере** (образ собран из этого репозитория, почта — Dovecot и Postfix из `make dev-mail`; запросы `curl` и скрипт на Python с настоящим входом); проверка зависимостей (`dotnet list package --vulnerable`, `pnpm audit`); сквозные проверки в браузере (Playwright, VIN-121). Внешнего пентеста не было.

## Итог

Критичных и серьёзных находок нет. Найдено и исправлено **3 мелких** замечания; ещё одно (нет ограничения отправки) закрыто следом, в VIN-141. Все пункты чек-листа выполнены.

## Принято без исправления

- `GET /api/v1/scheduled` при чтении переносит в «Черновики» письма, у которых пароль уже не принимается (`session_revoked`, VIN-107): у запроса GET есть побочное действие. Оно затрагивает только письма самого пользователя, идемпотентно, и защищено `SameSite=Strict`, а CSRF-вызов ничего не раскрывает. Оставлено (иначе письмо ждало бы следующего входа).
- `GET /api/v1/health` отдаёт номер версии: это нужно проверке состояния и поддержке; секретов нет.
- Исключения MailKit при непредвиденной ошибке попадают в журнал целиком (`Unhandled exception`): в них могут быть имена папок. Пароля нет: он не передаётся в сообщения исключений. Подробности только в журнале сервера, пользователю не отдаются.
- Подпись и проверка отправителя письма (`Authentication-Results`) верят только заголовкам доверенных `authserv-id` (`SenderCheck:TrustedAuthservIds`) — описано в `architecture.md`.

## Не входило и осталось

- Ограничение частоты **отправки** писем (вошедший или захвативший сессию мог слать письма без пределов) закрыто задачей **VIN-141**: `Security:SendRateLimit`, 429 с кодом `send_limit_reached`.
- Redis как хранилище сессий (несколько экземпляров, [ADR-0007](adr/0007-multiple-instances.md)): защита соединения с Redis — на стороне администратора (TLS, пароль); в VIN-126 это нужно описать.
- Внешний пентест, фаззинг MIME-разборщика и проверка конкретной установки администратора (reverse proxy, TLS) не выполнялись.
- Скан уязвимостей образа и подпись образа — сделано в VIN-123 ([image-security.md](image-security.md)); подпись и SBOM впервые появятся с пробным релизом (VIN-133).
