# Руководство администратора

Для тех, кто ставит и обслуживает Vinette: как задать настройки, что означает каждая, где что хранится, как смотреть журнал и метрики, как обновляться. Установка по шагам — в README (Docker) и в [install-bare-metal.md](install-bare-metal.md) (голое железо, systemd); отдельные темы вынесены в свои документы:

- [reverse-proxy.md](reverse-proxy.md) — HTTPS и прокси (nginx, Caddy, Traefik);
- [white-label.md](white-label.md) — название, логотип, цвет;
- [data-protection-keys.md](data-protection-keys.md) — шифрование ключей сертификатом;
- [mail-server.md](mail-server.md) — требования к почтовому серверу (IMAP, отправка, проверка отправителей);
- [backup-and-update.md](backup-and-update.md) — резервные копии, восстановление, обновление и откат;
- [security-audit.md](security-audit.md) и [SECURITY.md](../SECURITY.md) — что защищено и что хранится на сервере.

## Что такое Vinette и что ему нужно

Vinette не хранит почту. Это шлюз между браузером и вашим почтовым сервером: он входит на сервер **от имени пользователя** (адрес и пароль ящика), читает письма по IMAP, отправляет через submission (SMTP, порт 587 или 465) и показывает всё в браузере. Нужны:

- почтовый сервер с IMAP и submission (рассчитано на Dovecot и Postfix), доступный с машины, где работает Vinette;
- HTTPS перед приложением ([reverse-proxy.md](reverse-proxy.md)): cookie сессии `Secure`, по HTTP вход не работает;
- каталог для данных приложения (ключи шифрования, настройки пользователей, вложения в черновиках, очередь отложенной отправки); в Docker это том `/data`.

Пользователи входят своим адресом и паролем ящика, отдельных учётных записей Vinette нет.

## Как задаются настройки

Слои, от слабого к сильному (более сильный перекрывает слабый):

1. `appsettings.json` внутри приложения (значения по умолчанию);
2. **переменные окружения** `VINETTE_*`;
3. **файл** по пути из переменной `VINETTE_CONFIG` (JSON, образец — [appsettings.example.json](../deploy/config/appsettings.example.json)).

Важно: **файл сильнее переменных окружения.** Если в файле указан ключ, переменная окружения для него не действует. Файл из `appsettings.example.json` перечисляет все ключи, поэтому, взяв его целиком, вы получите значения файла и «не заработают» переменные. Оставьте в файле только то, что меняете.

Имя переменной: `VINETTE_` + путь ключа, где вложенность — двойное подчёркивание: `Imap:Host` → `VINETTE_Imap__Host`, `Security:LoginRateLimit:MaxFailuresPerIp` → `VINETTE_Security__LoginRateLimit__MaxFailuresPerIp`. Список — по номерам: `Security:TrustedProxies:0` → `VINETTE_Security__TrustedProxies__0`, следующий — `__1`.

Значения:

- **время и сроки** — `часы:минуты:секунды` (`00:00:30` — тридцать секунд, `02:00:00` — два часа) или `дни.часы:минуты:секунды` (`7.00:00:00` — неделя);
- **размеры** — в байтах (`20971520` = 20 МБ);
- **логические** — `true` и `false`; **цвета** — `#RRGGBB`.

Все настройки проверяются **при запуске**, а заданные каталоги данных (`DataProtection:KeysPath`, `Settings:Path`, `Attachments:Path`, `Scheduling:Path`) ещё и создаются и проверяются на запись: с неверным значением (например, цвет не в формате `#RRGGBB` или `Imap:Port` вне диапазона) приложение не стартует и пишет, какое именно. Изменения применяются после перезапуска.

Образец для Docker (минимум):

```yaml
services:
  vinette:
    image: ghcr.io/f1nn17/vinette:latest
    restart: unless-stopped
    environment:
      VINETTE_Imap__Host: mail.example.com
      VINETTE_Smtp__Host: mail.example.com
      VINETTE_Security__TrustedProxies__0: 172.20.0.0/24   # где стоит прокси, см. reverse-proxy.md
    volumes:
      - vinette-data:/data
volumes:
  vinette-data:
```

Каталоги данных в образе уже заданы переменными окружения на `/data/...`, поэтому достаточно примонтировать том в `/data`. В файле-образце те же ключи указывают на `/var/lib/vinette/...` — это пути для голого железа; **в контейнере с таким файлом каталог `/var/lib/vinette` недоступен**, и приложение не запустится: в журнале будет написано, какая настройка указывает на недоступный каталог. Либо уберите из файла ключи `Path`/`KeysPath`, либо замените на `/data/...`.

## Справочник настроек

В таблицах — значение по умолчанию. Если ключа нет в таблице, он не настраивается.

### Почтовый сервер: `Imap`

| Ключ | По умолчанию | Что делает |
| --- | --- | --- |
| `Host` | `localhost` | Имя или адрес почтового сервера (обязательно) |
| `Port` | `993` | Порт IMAP |
| `Security` | `Tls` | `Tls` (шифрование с первого байта), `StartTls` (переход на шифрование) или `None` (без шифрования, только для сервера на той же машине или в доверенной сети: пароль идёт открытым текстом; при запуске будет предупреждение) |
| `Timeout` | `00:00:30` | Предел на соединение и на каждый ответ сервера. Должен быть больше задержки Dovecot после неверных входов (до 15 с), иначе неверный пароль выглядит как поломка |
| `ConnectionIdleTimeout` | `00:05:00` | Соединение, которым не пользовались, закрывается, чтобы не занимать сервер; следующий запрос откроет новое |
| `MaxConnectionsPerUser` | `5` | Соединений с одним ящиком (по одному на вошедший браузер или устройство). Остальные запросы ждут, потом получают «занято» |
| `MaxConnections` | `200` | Соединений всего. **Держите меньше, чем почтовый сервер разрешает с одного адреса** (в Dovecot, например, `mail_max_userip_connections` и предел процессов службы `imap`) |
| `ConnectionWaitTimeout` | `00:00:10` | Сколько запрос ждёт свободного соединения, прежде чем получит 503 с `Retry-After` |
| `IdleRestart` | `00:25:00` | Как часто обновляется соединение, следящее за входящими: сервер рвёт слишком долгое ожидание (предел по RFC — 29 минут) |
| `IdleGrace` | `00:01:00` | Сколько слежение за ящиком живёт после ухода последнего браузера |
| `MaxIdleConnections` | `200` | Следящих соединений всего (по одному на ящик); учитывайте вместе с `MaxConnections` |
| `MaxViewableMessageBytes` | `33554432` | Самое большое письмо (в байтах), которое открывается и из которого скачиваются вложения; больше — «слишком большое для показа». Письмо разбирается в памяти: поднимайте, только если хватает памяти |
| `AllowInvalidCertificate` | `false` | Не проверять сертификат сервера. **Только для тестов:** пароль можно перехватить; при запуске будет предупреждение |

### Отправка: `Smtp`

| Ключ | По умолчанию | Что делает |
| --- | --- | --- |
| `Host` | `localhost` | Сервер приёма почты от пользователей (submission); пользователь входит на нём своими адресом и паролем |
| `Port` | `587` | `587` с `StartTls` или `465` с `Tls` |
| `Security` | `StartTls` | Как у `Imap` |
| `Timeout` | `00:00:30` | Предел на соединение и ответ |
| `AllowInvalidCertificate` | `false` | Как у `Imap` |

### Вход и сессии: `Session`, `Redis`, `Security:LoginRateLimit`

| Ключ | По умолчанию | Что делает |
| --- | --- | --- |
| `Session:Store` | `InMemory` | Где хранятся сессии: `InMemory` (в памяти процесса: один экземпляр, при перезапуске все выходят) или `Redis` (общие для нескольких экземпляров и переживают перезапуск) |
| `Session:IdleTimeout` | `02:00:00` | Сессия кончается после стольких часов без действий |
| `Session:MaxLifetime` | `7.00:00:00` | Предельный срок сессии, как бы ни пользовались; не меньше `IdleTimeout` |
| `Session:RememberMeLifetime` | `30.00:00:00` | Срок сессии у тех, кто отметил «Оставаться в системе» (и простоя, и предельный) |
| `Redis:ConnectionString` | пусто | Строка подключения StackExchange.Redis (`redis:6379,password=...,ssl=true`). Обязательна при `Session:Store = Redis`. Содержит секрет, в журнал не попадает |
| `Redis:KeyPrefix` | `vinette:` | Приставка ключей, чтобы делить Redis с другими приложениями |
| `Security:LoginRateLimit:MaxFailuresPerAccount` | `5` | Неверных паролей для одного ящика до блокировки (блокировка растёт: 1, 2, 4… минуты) |
| `Security:LoginRateLimit:MaxFailuresPerIp` | `20` | Неверных паролей с одного адреса клиента, какие бы ящики он ни пробовал |
| `Security:LoginRateLimit:Window` | `00:15:00` | Старые ошибки забываются через это время без новых |
| `Security:LoginRateLimit:MaxLockout` | `00:15:00` | Самая долгая блокировка |
| `Security:LoginRateLimit:MaxAttemptsPerMinutePerIp` | `30` | Попыток входа в минуту с одного адреса, удачных и нет (защищает почтовый сервер) |
| `Security:SendRateLimit:MessagesPerHour` | `60` | Писем, которые один ящик может отправить или отложить за час (письмо нескольким людям — одно). `0` — без ограничения этого вида |
| `Security:SendRateLimit:RecipientsPerHour` | `200` | Разных получателей (кому, копия, скрытая) у одного ящика за час |
| `Security:SendRateLimit:MessagesPerDay` | `300` | Писем за сутки (24 часа) |
| `Security:SendRateLimit:RecipientsPerDay` | `600` | Получателей за сутки |

Ограничение отправки защищает от спама, если сессию захватят: письмо сверх предела получает `429` и пользователь видит, через сколько минут (или часов) можно отправить следующее. Счётчики хранятся в памяти: при нескольких экземплярах предел действует на каждый отдельно, после перезапуска счёт начинается заново. Отложенное письмо считается в момент, когда его откладывают. Ответ о прочтении и уведомления не считаются. Если у вас массовые рассылки через ящики, увеличьте пределы или поставьте `0`.

Ограничения по адресу работают, только если приложение знает настоящий адрес клиента: за прокси задайте `Security:TrustedProxies` ([reverse-proxy.md](reverse-proxy.md)).

### Безопасность: `Security`, `DataProtection`, `SenderCheck`

| Ключ | По умолчанию | Что делает |
| --- | --- | --- |
| `Security:TrustedProxies` | пусто | Адреса и сети (CIDR) прокси, которым верят `X-Forwarded-*`. Без списка заголовки игнорируются. `0.0.0.0/0` не принимается |
| `Security:TrustedOrigins` | пусто | Адреса сайта (`https://mail.example.com`), с которых допустимы изменяющие запросы, кроме собственного; нужно, если адрес в браузере не совпадает с тем, что видит приложение |
| `Security:Headers:HstsMaxAge` | `365.00:00:00` | Срок HSTS; `00:00:00` выключает. Отправляется только по HTTPS |
| `Security:Headers:CspReportOnly` | `false` | Политика содержимого только сообщает о нарушениях, ничего не блокируя (для поиска, что нужно нестандартной схеме) |
| `Security:Headers:ConnectSources` | пусто | Другие адреса, к которым странице можно подключаться (например, `wss://live.example.com`, если канал обновлений отдаётся с другого имени) |
| `DataProtection:KeysPath` | пусто | Каталог ключей шифрования паролей. **Должен быть постоянным**, иначе при перезапуске все выходят. В образе `/data/keys` |
| `DataProtection:CertificatePath` и родственные | пусто | Шифрование ключей сертификатом: [data-protection-keys.md](data-protection-keys.md) |
| `SenderCheck:TrustedAuthservIds` | пусто | Имена, которыми ваш сервер начинает заголовок `Authentication-Results` (обычно имя сервера, `myhostname` в Postfix). Только такой заголовок на самом верху письма может дать отправителю отметку «подтверждён». Пусто — берётся `Imap:Host` |

### Данные пользователей: `Settings`, `Attachments`, `Scheduling`

| Ключ | По умолчанию | Что делает |
| --- | --- | --- |
| `Settings:Store` | `File` | Где хранятся настройки пользователей (плотность, язык, подписи, цвета меток, доверенные отправители): файлы в каталоге |
| `Settings:Path` | каталог данных учётной записи процесса | Каталог настроек. Постоянный; в образе `/data/settings` |
| `Attachments:Path` | временный каталог | Загруженные, но ещё не отправленные файлы. Постоянный; в образе `/data/attachments`. При нескольких экземплярах общий |
| `Attachments:MaxFileBytes` | `20971520` | Самый большой файл (20 МБ). При отправке файл растёт примерно на треть, а у почтового сервера свой предел письма: держите сумму вложений ниже его предела, делённого на 1,4 |
| `Attachments:MaxTotalBytes` | `26214400` | Все ожидающие файлы одного ящика (25 МБ) |
| `Attachments:MaxFiles` | `20` | Файлов у одного ящика |
| `Attachments:Lifetime` | `24:00:00` | Через сколько удаляется файл, который так и не отправили |
| `Scheduling:Path` | временный каталог | Очередь отложенной отправки: на письмо два файла (описание с зашифрованным паролем ящика и само письмо). Постоянный; в образе `/data/scheduled` |
| `Scheduling:Enabled` | `true` | Отправляет ли этот экземпляр письма, чей час настал. **При нескольких экземплярах включите ровно на одном**, иначе письмо уйдёт дважды |
| `Scheduling:PollInterval` | `00:00:30` | Как часто смотреть очередь |
| `Scheduling:MinDelay` | `00:01:00` | Раньше, чем через это время, письмо отложить нельзя |
| `Scheduling:MaxDelay` | `7.00:00:00` | Позже, чем через это время, отложить нельзя; столько же (плюс `RetryFor` и сутки) хранится зашифрованный пароль ящика |
| `Scheduling:MaxPerMailbox` | `50` | Отложенных писем у одного ящика |
| `Scheduling:RetryFor` | `01:00:00` | Сколько после назначенного часа пробовать, если почтовый сервер недоступен; потом письмо уходит в «Черновики» |
| `Scheduling:RetryEvery` | `00:05:00` | Пауза между попытками |

Ключи всех каталогов — с одной оговоркой: если каталог не задан, берётся временный и **данные пропадут вместе с контейнером**. Для всех четырёх (`DataProtection:KeysPath`, `Settings:Path`, `Attachments:Path`, `Scheduling:Path`) нужен постоянный том.

### Картинки в письмах: `ExternalImages`

Картинки из сети браузер читателя не грузит никогда (иначе отправитель узнал бы, кто и когда открыл письмо): когда пользователь просит их показать, приложение скачивает их само и вставляет в письмо.

| Ключ | По умолчанию | Что делает |
| --- | --- | --- |
| `Enabled` | `true` | Можно ли показывать внешние картинки; `false` — они скрыты всегда |
| `MaxImageBytes` | `2000000` | Самая большая картинка |
| `MaxTotalBytes` | `10000000` | Картинок на одно письмо всего |
| `MaxImages` | `30` | Картинок на одно письмо |
| `RequestTimeout` | `00:00:05` | Время на одну картинку, с переходами |
| `TotalTimeout` | `00:00:10` | Время на все картинки письма |
| `MaxRedirects` | `3` | Переходов (каждый проверяется как первый адрес) |
| `AllowedPorts` | `[80, 443]` | Порты, с которых берутся картинки |
| `AllowPrivateAddresses` | `false` | **Никогда не включайте на настоящем сервере:** письмо смогло бы заставить приложение читать страницы вашей внутренней сети |

### Внешний вид: `Branding`

Название, логотип, значок вкладки, акцентный цвет, подпись и «Работает на Vinette»: [white-label.md](white-label.md).

### Метрики: `Metrics`

| Ключ | По умолчанию | Что делает |
| --- | --- | --- |
| `Enabled` | `false` | Включает `GET /metrics` в формате Prometheus |
| `BearerToken` | пусто | Токен, который присылает сборщик (`Authorization: Bearer ...`); не короче 16 знаков. Сгенерируйте длинный случайный: `openssl rand -hex 32` |

## Где что хранится

| Что | Где | Что будет, если потерять |
| --- | --- | --- |
| Письма | **на вашем почтовом сервере**, Vinette их не хранит | ничего (Vinette читает и пишет их там) |
| Ключи шифрования паролей | `DataProtection:KeysPath` (`/data/keys`) | все выходят из системы; письма из очереди отложенной отправки попадают в «Черновики». Ключи зашифруйте сертификатом ([data-protection-keys.md](data-protection-keys.md)) |
| Настройки пользователей | `Settings:Path` (`/data/settings`) | пользователи начинают с настроек по умолчанию |
| Вложения, которые ещё не отправили | `Attachments:Path` (`/data/attachments`) | придётся прикрепить заново |
| Очередь отложенной отправки | `Scheduling:Path` (`/data/scheduled`) | отложенные письма не уйдут |
| Сессии | в памяти процесса или в Redis | все выходят и входят заново |

Каталоги читает и пишет только пользователь процесса (в образе UID 1654, на голом железе `vinette`); в unit-файле systemd каталог данных создаётся с правами `0700`. Пароль ящика хранится только зашифрованным и только на время сессии или ожидания отложенного письма ([SECURITY.md](../SECURITY.md)).

## Несколько экземпляров

Можно запускать несколько экземпляров за одним адресом ([ADR-0007](adr/0007-multiple-instances.md)). Нужно:

- `Session:Store = Redis` и `Redis:ConnectionString` (защита соединения с Redis — пароль и TLS — на вашей стороне);
- **общие** каталоги `DataProtection:KeysPath`, `Attachments:Path`, `Scheduling:Path` (и `Settings:Path`) и общий сертификат, если ключи шифруются;
- `Scheduling:Enabled = true` на **одном** экземпляре, на остальных `false`.

## Журнал и проверка состояния

- Журнал — строки JSON в стандартный вывод (в Docker смотрите `docker logs`): время, уровень, источник, сообщение и поля. Пароли, cookie, токены и тела писем туда не попадают; адрес ящика и адрес клиента попадают (входы, блокировки).
- **Предупреждения при запуске**, на которые стоит смотреть: ключи шифрования не сохраняются (`KeysPath` не задан) или лежат открытыми (нет сертификата), соединение с почтовым сервером не зашифровано, проверка его сертификата отключена, акцент слишком светлый.
- Проверка состояния: `GET /api/v1/health` отвечает `{"status":"ok","version":"…"}` без входа. В Docker образе уже есть проверка (`HEALTHCHECK`), `docker ps` покажет `healthy`.
- Метрики: включите `Metrics:Enabled` и задайте токен; Prometheus опрашивает `/metrics` с `Authorization: Bearer`. В метриках нет адресов и данных писем: только счётчики соединений, ошибок и длительности команд.

## Обновление

1. Прочитайте `CHANGELOG.md`: в разделах новых версий написано, какие ключи появились и что изменилось.
2. Сделайте копию тома `/data` (в особенности каталога ключей и сертификата, если он есть).
3. Замените образ на новую версию (`ghcr.io/f1nn17/vinette:0.1.0`, тег `latest` двигается с каждым выпуском: для боевой установки указывайте точную версию) и перезапустите. Каталоги данных остаются, пользователи остаются в системе, если сессии в Redis и ключи на месте; при `InMemory` все войдут заново.
4. Откат: верните прежнюю версию образа. Если обновление что-то записало в данные, которые прежняя версия не читает, верните копию тома.

Подробнее о копиях, восстановлении и откате — [backup-and-update.md](backup-and-update.md).

## Когда что-то не работает

| Симптом | Вероятная причина |
| --- | --- |
| Приложение не стартует, в журнале ошибка проверки настроек | неверное значение или формат (цвет, время, список адресов прокси): в сообщении названа настройка |
| Вход не удаётся, хотя пароль верный | почтовый сервер недоступен с машины Vinette (`Imap:Host`/`Port`/`Security`) или `Imap:Timeout` меньше задержки сервера после неверных входов |
| «Почта занята», `503` с `Retry-After` | исчерпаны соединения: `MaxConnectionsPerUser` (много браузеров одного ящика) или `MaxConnections`; не больше, чем разрешает сервер |
| После перезапуска все выходят | сессии в памяти (`Session:Store = InMemory`) или ключи шифрования не на постоянном томе |
| Приложение не запускается, в журнале «…does not exist and cannot be created, or the application cannot write to it» | каталог одной из настроек `DataProtection:KeysPath`, `Settings:Path`, `Attachments:Path`, `Scheduling:Path` недоступен для записи пользователю процесса: сообщение называет настройку; создайте каталог и дайте права или поправьте путь |
| Письма из очереди ушли в «Черновики» | не удалось отправить (сервер отклонил, пароль уже не принимается, сервер недоступен дольше `Scheduling:RetryFor`) или потеряны ключи |
| Все заблокированы после нескольких неверных паролей одного человека | приложение за прокси не знает настоящих адресов: `Security:TrustedProxies` ([reverse-proxy.md](reverse-proxy.md)) |
| Переменная окружения «не действует» | тот же ключ задан в файле `VINETTE_CONFIG`: файл сильнее |
