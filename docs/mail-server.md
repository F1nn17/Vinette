# Требования к почтовому серверу

Vinette работает с вашим почтовым сервером как обычный почтовый клиент, только в браузере. Рассчитан на **Dovecot** (IMAP) и **Postfix** (приём почты от пользователей), с **Rspamd** для проверки отправителей; другие серверы подойдут, если умеют то же самое. Здесь — что именно нужно, что желательно и как это проверить.

## Коротко

| | Нужно | Желательно (иначе работает хуже) |
| --- | --- | --- |
| **IMAP** | вход по адресу и паролю ящика; шифрование (TLS на 993 или STARTTLS на 143); UID; ключевые слова-метки (`PERMANENTFLAGS \*`); поиск с UTF-8; `APPEND` | `IDLE`, `CONDSTORE`, `QRESYNC`, `MOVE`, `SPECIAL-USE`, `QUOTA`, `ID`, `PREVIEW` |
| **Отправка** | submission с входом тем же адресом и паролем: 587 (STARTTLS) или 465 (TLS) | |
| **Проверка отправителя** | | заголовок `Authentication-Results` от вашего сервера (Rspamd, opendkim, opendmarc) |

## IMAP

Vinette входит на сервер **от имени пользователя**: логин — то, что человек ввёл на экране входа, пароль — его пароль. Если у вас логин не полный адрес, а короткое имя (как в тестовом GreenMail), человек вводит его так же; у Dovecot в боевой работе обычно полный адрес.

### Обязательное

- **Шифрование:** IMAPS на 993 (`Imap:Security = Tls`) или STARTTLS на 143 (`StartTls`). Без шифрования (`None`) пароль идёт открытым текстом; допустимо только на той же машине или в доверенной сети, при запуске будет предупреждение. Сертификат сервера должен проверяться (`Imap:AllowInvalidCertificate = false`): либо от публичного центра, либо ваш, которому доверяет машина с Vinette.
- **Ключевые слова.** Метки (раздел «Метки») — это ключевые слова IMAP на письмах. Сервер должен разрешать создавать новые: в ответе на `SELECT` в `PERMANENTFLAGS` есть `\*`. У Dovecot это так по умолчанию.
- **Поиск с UTF-8.** Поиск по кириллице идёт командой `SEARCH` с `CHARSET UTF-8`. Проверено на Dovecot: слова находятся в письмах в UTF-8, KOI8-R и Windows-1251, регистр не важен. Сервер, не понимающий UTF-8 в поиске, найдёт только латиницу.
- **Папки по умолчанию:** «Входящие» (`INBOX`) должна быть. Остальные (черновики, отправленные, архив, спам, корзина) Vinette находит сам (см. ниже). Если какой-то нет, соответствующее действие недоступно или письмо оставляется на месте.

### Расширения, которые ускоряют и улучшают работу

Каждого можно не иметь: Vinette проверяет возможности сервера при каждом соединении и переходит на запасной путь.

| Расширение | Для чего | Без него |
| --- | --- | --- |
| `IDLE` | новые письма и изменения появляются в открытом ящике сразу | Vinette опрашивает сервер раз в 30 секунд: письма приходят с задержкой до 30 секунд |
| `CONDSTORE`, `QRESYNC` | после обрыва связи узнать, что изменилось, не читая ящик заново | после обрыва список читается заново целиком |
| `MOVE` | перенос письма в архив, спам, корзину одной командой | копирование и затем удаление: дольше и при обрыве может остаться копия |
| `SPECIAL-USE` | сервер сам говорит, какая папка «Отправленные», «Спам» и т. д. | роли папок угадываются по именам на английском и русском (`Sent`, `Sent Items`, `Отправленные`, `Trash`, `Корзина`, `Archive`, `Архив`, `Junk`, `Спам`, `[Gmail]/Spam`, `INBOX.Sent` и др.); серверное имя всегда главнее |
| `QUOTA` | полоса «Занято N из M» в боковой панели | полосы нет |
| `PREVIEW` | начало текста для списка писем одной командой | Vinette читает начало письма сам: список медленнее |
| `ID` | Vinette называет себя серверу (в журнале сервера видно, что это Vinette) | не называет |

`METADATA` (RFC 5464) Vinette не использует; скрипт проверки (ниже) его только отмечает.

### Сколько соединений

Каждый вошедший браузер держит одно соединение с сервером (пока человек работает), и ещё одно на ящик следит за новыми письмами. Ограничения Vinette: `Imap:MaxConnectionsPerUser` (5 на ящик), `Imap:MaxConnections` (200 всего), `Imap:MaxIdleConnections` (200). **Они должны быть меньше, чем разрешает сервер с одного адреса**: все соединения идут с адреса Vinette. В Dovecot смотрите, например, `mail_max_userip_connections` (число соединений одного пользователя с одного адреса) и предел процессов службы `imap`. Если сервер режет раньше, пользователи видят «Почта занята».

### Задержка после неверных входов

Dovecot намеренно замедляет ответ при неверных паролях (до 15 с при многих ошибках с одного адреса). `Imap:Timeout` (30 с по умолчанию) должен быть больше этой задержки, иначе неверный пароль похож на поломку. Все входы идут с адреса Vinette, поэтому замедление по адресу (и блокировки, если у вас есть fail2ban и подобное) могут задеть всех пользователей сразу: если так, настройте их так, чтобы адрес Vinette не блокировался целиком (у Dovecot задержкой управляет `auth_failure_delay`). Своё ограничение по пользователям и адресам у Vinette есть (`Security:LoginRateLimit`).

## Отправка (submission)

Vinette отдаёт письмо на **порт submission** (587 с STARTTLS или 465 с TLS), а не на 25, и входит там **тем же адресом и паролем**, что и в IMAP. Для Postfix это типичная настройка:

```
# /etc/postfix/master.cf
submission inet n - n - - smtpd
  -o syslog_name=postfix/submission
  -o smtpd_tls_security_level=encrypt
  -o smtpd_tls_auth_only=yes
  -o smtpd_sasl_auth_enable=yes
  -o smtpd_sasl_type=dovecot
  -o smtpd_sasl_path=private/auth
  -o smtpd_relay_restrictions=permit_sasl_authenticated,reject
```

Для 465 (TLS с первого байта) то же с `submissions` и `-o smtpd_tls_wrappermode=yes`. Вход проверяет Dovecot (`smtpd_sasl_type=dovecot`), поэтому пароль один на IMAP и отправку.

Важное:

- **Копию в «Отправленные» кладёт сам Vinette** (в ящик по IMAP после отправки). Не настраивайте сервер так, чтобы он тоже сохранял копии (например, `always_bcc` себе), иначе будут дубли.
- **Отправитель — адрес ящика пользователя.** Если сервер проверяет, что отправитель совпадает с логином (`smtpd_sender_login_maps`, `reject_sender_login_mismatch`), Vinette проходит проверку.
- **Скрытые получатели** (Bcc) идут только в конверте и в письме не пишутся.
- Размер письма: у сервера свой предел (`message_size_limit` в Postfix). Вложения растут примерно на треть при отправке; держите `Attachments:MaxTotalBytes` ниже предела сервера, делённого на 1,4.
- Тот же сертификат, та же проверка: `Smtp:Security` и `Smtp:AllowInvalidCertificate`, как у IMAP.

## Проверка отправителей (Rspamd)

Метка «Подтверждён» рядом с адресом отправителя и предупреждение «Письмо может быть не от того, за кого себя выдаёт» строятся по заголовку `Authentication-Results`, который добавляет **ваш** сервер при приёме письма (RFC 8601). Vinette верит ему, только если:

- заголовок **самый верхний** в письме (нижние мог написать отправитель);
- его имя (`authserv-id`) — одно из имён вашего сервера: по умолчанию это `Imap:Host`, иначе задайте `SenderCheck:TrustedAuthservIds` (обычно имя, которое у Postfix в `myhostname`).

Если ваш сервер не добавляет такой заголовок, письма просто не получают отметки «подтверждён» (а подозрительными становятся только те, у кого заголовок явно сообщает о провале проверки). Заголовок добавляют Rspamd (модуль `milter_headers` с `authentication-results`), opendkim, opendmarc; сверьтесь с документацией вашей версии, и проверьте, что `authserv-id` в письме совпадает с `SenderCheck:TrustedAuthservIds`.

## Как проверить свой сервер

Скрипт из репозитория подключается по IMAP, входит и выводит возможности сервера:

```bash
bash deploy/docker/dev-mail/check-capabilities.sh mail.example.com 143 user@example.com 'пароль'
```

(порт 143 — открытое соединение; для 993 скрипт не подходит, он без TLS. Проверьте на закрытом тестовом ящике или из сети сервера.) Результат на тестовом Dovecot 2.4:

```
Required:
  ok       SPECIAL-USE
  ok       IDLE
  ok       MOVE
  ok       CONDSTORE
  ok       QRESYNC
  ok       QUOTA
  ok       ID
  ok       METADATA
Optional:
  yes      PREVIEW
  ...
```

Заголовок «Required» в скрипте означает «должно быть на нашем тестовом сервере» (по ним мы проверяем запасные пути и работу в лучшем случае), а не «без этого Vinette не запустится»: что действительно обязательно, перечислено выше.

Пример для Dovecot 2.4: чтобы объявлялся `METADATA`, нужен словарь атрибутов (`deploy/docker/dev-mail/dovecot.cf`):

```
mail_attribute {
  dict file {
    path = %{home}/dovecot-attributes
  }
}
imap_metadata = yes
```

Vinette его не требует, пример нужен только для проверки целиком «зелёного» сервера.

## Что проверено

Vinette проходит интеграционные тесты и сквозные сценарии (вход, чтение, поиск, метки, отправка, черновики, отложенная отправка, обновления в реальном времени) на настоящих Dovecot и Postfix (`docker-mailserver`), и часть сценариев на GreenMail, который не умеет `SPECIAL-USE` и `QRESYNC`: это и проверка запасных путей. На других серверах (Cyrus, Courier, Exchange, Gmail по IMAP) полный набор сценариев не гонялся: если найдёте расхождение, сообщите (`CONTRIBUTING.md`).
